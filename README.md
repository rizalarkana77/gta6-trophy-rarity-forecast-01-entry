# GTA VI trophy rarity forecast — week one

Forecasts, for each of Grand Theft Auto VI's 55 PlayStation 5 trophies, the earn rate
Exophase will print at 2026-11-26T00:00:00Z — as five quantiles (5%, 25%, 50%, 75%, 95%)
per trophy. Entry for make.fun competition `gta6-trophy-rarity-forecast-01`.

## The idea, from first principles

An earn rate is **earners / players-tracked**, and both move:

- **New players dilute every rate.** They join Exophase having earned nothing yet.
  Launch night proved it: the page sat at 638 players with every rate frozen, then its
  first refresh showed 3,868 players and *every* rate lower. A forecaster that only
  extends the last read misses this completely.
- **Existing players progress.** Each trophy's rate follows a completion curve: it rises
  fast while the first wave of players reaches it, then flattens as the rest are the
  slow ones. A straight line in log time keeps the early slope forever and overshoots
  the target by tens of points.

So `main.ts` fits, per trophy, a **saturating curve** — `rate(t) = Rinf / (1 + (t0/t)^k)`
in game-age `t` — to the case's own history by grid search, and shrinks it toward a
**class prior** built from how Rockstar trophies progress in week one: story chapters
finish fastest, then named missions and easy activities, then side strands and grinds,
with 100% completion and the platinum slowest of all (almost nobody holds them in week
one). When the page has not refreshed at all since release and the target is hours away,
the forecast predicts the coming refresh's dilution instead of the flat page.

**Spreads are honest.** The spread is the fit's residual scale plus terms for refresh
staleness (the answering read prints the page as of its own last refresh) and dilution,
widening with the horizon — wide enough to cover a refresh, narrow enough not to pay
for width at every quantile.

## Grade-local (simulated worlds with known answers)

No local grade exists for this competition — the server grades every entry — so the
forecaster was tested on synthetic cases generated by a cohort model (players join over
time, earn with play-age; Exophase refreshes freeze the page; the launch-night dip is
reproduced: 638 players, ~1% rates, then 3,868 with lower rates). Two scenario sets,
16 + 8 cases (final-like 4.5-day horizons and practice-like 90-minute ones):

| program | final loss | practice loss |
|---|---|---|
| this entry | **0.253** / **0.260** | **0.268** / — |
| house trend baseline | 0.268 / 0.394 | 0.374 / — |
| house persistence baseline (starter) | 0.486 / — | 0.374 / — |

Mean pinball loss on the logit scale, lower is better. The entry beats both house
baselines on final-like and practice-like cases, with a typical median miss of
~1–2.5 points (vs 2.7–4.9 for the baselines) and ~0.92–0.98 90% coverage.

## Running it

Node 22, standard library only, no network, deterministic (two runs write byte-identical
output), ~0.2 s per case:

```sh
mkdir -p out && MAKEFUN_INPUT_DIR=input MAKEFUN_OUTPUT_DIR=out node main.ts
```

It reads every `<id>.in` in the input directory and writes `<id>.out`:
`{"trophies":[{"id":n,"q":[q05,q25,q50,q75,q95]}]}`.
